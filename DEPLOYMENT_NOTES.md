## Architecture of the deployment

```
Browser ──► Vercel (static React/Vite build)
                │  VITE_API_BASE_URL = https://ethara-backend-9kbg.onrender.com/api/v1
                ▼
        Render Web Service (FastAPI, Python 3, Oregon)
                │
                ▼
        Render Managed PostgreSQL 18 (ethara-db)
```

- **Frontend** → Vercel (static hosting for the Vite build), deployed via the Vercel CLI.
- **Backend** → Render Web Service (Python runtime), provisioned from `render.yaml`.
- **Database** → Render Managed PostgreSQL, provisioned by the same Blueprint.

## Backend — Render (Blueprint)

The backend + database are described as infrastructure-as-code in [`render.yaml`](./render.yaml):

- `ethara-db` — free managed PostgreSQL.
- `ethara-backend` — free web service.
  - **Build:** `pip install -r requirements.txt`
  - **Start:** `python -m scripts.bootstrap && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
  - **Health check:** `/health`
  - `DATABASE_URL` is injected from `ethara-db`; `JWT_SECRET_KEY` is auto-generated;
    `CORS_ORIGINS` is set to the Vercel URL.

**Deploy steps:**
1. Push the repo to GitHub.
2. Render Dashboard → **New → Blueprint** → select the repo → it reads `render.yaml`.
3. Enter `CORS_ORIGINS` = the Vercel frontend URL when prompted → **Deploy Blueprint**.
4. Render builds, provisions Postgres, and boots the service.

### Notable fix: empty migration → self-bootstrap
The initial Alembic migration was an autogenerated stub (`upgrade()` was `pass`), so it created
**no tables** — locally this was masked because `scripts/seed_db.py` calls
`Base.metadata.create_all()`. On the fresh Render database, migrations created nothing and every
query 500'd.

Because the Render **free tier has no Shell / One-Off Jobs**, we couldn't seed manually. The fix is
[`backend/scripts/bootstrap.py`](./backend/scripts/bootstrap.py), run at container start:
1. `Base.metadata.create_all()` — ensures all tables exist (idempotent).
2. Seeds demo data **only if the database is empty** — so cold-start restarts never wipe data.

This makes deployments fully self-healing: a `git push` to `main` auto-redeploys, and the first boot
creates the schema and seeds ~5,000 employees / 5,600 seats / 11 projects / demo users.

### Database URL normalization
Managed hosts hand out `postgres://` URLs; SQLAlchemy needs `postgresql://`.
`app/core/config.py` normalizes this via a Pydantic field validator.

## Frontend — Vercel (CLI)

Config: [`frontend/vercel.json`](./frontend/vercel.json) (framework `vite`, SPA rewrites so client-side
routes don't 404).

**Deploy steps:**
```bash
cd frontend
vercel login                     # authenticate (one time)
# set the live backend URL for the build:
vercel env add VITE_API_BASE_URL production   # value: https://ethara-backend-9kbg.onrender.com/api/v1
vercel deploy --prod             # build + deploy
```

The build bakes `VITE_API_BASE_URL` into the bundle. Every `git push` (or `vercel deploy --prod`)
re-deploys.
